# Feature Specification: Backlog исправлений (F1–F12)

**Status**: `Ready`
**Источник**: `Plan/FIXES-PLAN.md` (архитектурный обзор слабых мест).

## Overview

Пакет исправлений слабых мест, найденных при архитектурном обзоре: DI провайдеров, хрупкие системные интеграции, MVVM, RPC-сессия, атомарность настроек, секреты/HTTPS, таймауты, контракт ошибок, god-хендлеры, Domain-чистота, безопасность парсера, тесты.

**Приоритеты:** P0 — критично (данные/security/производительность), P1 — важно, P2 — чистый долг.

## Requirements

### FR-1 — Провайдеры отвязаны от UI (F1, P1)
- **GIVEN** плагин поиска **WHEN** сконструирован **THEN** он не содержит `using Avalonia` (кроме `*LoginWindow`) и конструктор принимает зависимости через DI (не parameterless).
- **GIVEN** HTTP-логика провайдера **WHEN** выполняется **THEN** нет обращений к `Dispatcher.UIThread`; системные вызовы маршалируются в точке вызова.

### FR-2 — Надёжные системные интеграции (F2, P1)
- **GIVEN** трей/активация окна **WHEN** работают **THEN** нет освобождения нативной библиотеки до завершения вызовов.
- **GIVEN** вызов `wmctrl` **WHEN** утилита не установлена **THEN** обрабатывается без падения (лог/понятная ошибка).
- RuTracker WebLogin изолирован за интерфейсом (fallback без браузера).

### FR-3 — Чистый MVVM без service locator (F3, P1)
- **GIVEN** новый VM **WHEN** создан **THEN** не использует `AppServices` и не обращается к `Application.Current`.
- Окна/диалоги — через DI-фабрики; `TorrentsViewModel` разделён на под-VM.
- VM-тесты (`tests/TransmissonNET.App.Avalonia.Tests`, `Avalonia.Headless`) покрывают основные сценарии.

### FR-4 — RPC-сессия переиспользуется (F4, P0)
- **GIVEN** процесс **WHEN** опрашивает торренты **THEN** один `HttpClient`, кешированный `_sessionId`; список торрентов за 1 запрос (без лишних `session-get`/`speed-get`).
- 409-retry остаётся корректным при кеше.

### FR-5 — Атомарная запись настроек (F5, P0)
- **GIVEN** сохранение настроек **WHEN** вызывается **THEN** запись атомарна (tmp + `File.Move(overwrite: true)`).
- **GIVEN** битый `settings.json` при старте **WHEN** приложение загружается **THEN** не падает — читает tmp/бэкап или возвращает default с логом.

### FR-6 — Секреты и HTTPS (F6, P0)
- **GIVEN** пароль daemon **WHEN** сохраняется **THEN** не хранится plaintext (libsecret/Keyring или ключ с правами 0600); в DTO маскируется.
- Куки провайдеров — не plaintext (или права 0600 минимум); не логируются.
- `DaemonConnection.RpcUrl` поддерживает `https://`; схема валидируется в `SettingsValidator`.

### FR-7 — Явные таймауты (F7, P1)
- **GIVEN** сетевой/процессный вызов **WHEN** выполняется **THEN** ограничен таймаутом (`HttpClient.Timeout`/CTS, `DesktopProcessRunner`, `HandlerInvoker`).

### FR-8 — Единый контракт ошибок (F8, P1)
- **GIVEN** любая ошибка в хендлере **WHEN** доходит до UI **THEN** единый результат (success/typed error: код + сообщение + details); UI не показывает сырые исключения (только локализованные).

### FR-9 — Разделить god-хендлер действий (F9, P2)
- **GIVEN** команда над торрентом (старт/стоп/удаление/проверка/…)**WHEN** вызывается **THEN** отдельный протестированный use case (не `switch` в `ExecuteTorrentActionHandler`).

### FR-10 — Domain без UI-примеси (F10, P2)
- **GIVEN** Domain-модели **WHEN** изменяются **THEN** не содержат UI-настроек (колонки/тема); приоритет — единый `enum`; хендлеры возвращают единый вид (DTO).

### FR-11 — Парсер .torrent защищён от DoS (F11, P1)
- **GIVEN** злонамеренный bencode (глубокая вложенность/огромный словарь/большой файл) **WHEN** парсится **THEN** корректная ошибка, без зависания/падения (лимиты глубины, числа элементов, размера до чтения в память).

### FR-12 — Закрыть пробелы в тестах (F12, P1)
- **GIVEN** существующие модули **WHEN** прогоняются тесты **THEN** покрыты: ошибки RPC (401/500), отсутствующие поля, битый JSON, кеш сессии, параллельные вызовы, клиенты провайдеров, single-instance/трей, VM-логика.

## Non-Goals

- Добавление новой функциональности (только качество/надёжность/безопасность существующей).
- Изменение `NavigationService` (enum-переключатель сохраняется).
- Полное шифрование куки сверх прав 0600 (опционально).

## Success Criteria

- [ ] Для каждой FR — её acceptance-критерии выполнены.
- [ ] `dotnet test` зелёные после каждого пункта.
- [ ] P0 (FR-4/5/6) закрыты первыми.

## Edge Cases & Error Handling

- EC-1 — Сбой в момент записи настроек не теряет предыдущую копию (tmp+rename).
- EC-2 — Параллельные обновления RPC не создают гонку за session-id.
